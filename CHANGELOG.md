# Changelog

## [Unreleased]

### Added
- Added `tests/test_setup_server_files.py`, which statically checks that the `SERVER_FILES` array in `setup.sh` lists `server/trivy_server.py` and every local `server/` module it imports, directly or transitively (without running `setup.sh` or touching the network). It covers the different Python import forms, a negative case for a missing module, and malformed array formats, so a `curl ... setup.sh | bash` install cannot ship with a missing file.
- Added a `--ensure-tools` flag to `server/trivy_server.py`, safe to call in the background from a Claude Code plugin `SessionStart` hook:
  - **Offline fast path, standard library only**: before `_bootstrap()` runs it checks that the venv deps are current (`.tomofound-deps == _DEPS_VERSION` and the venv Python exists), that the ATR catalog matches `atr_catalog.ATR_PIN`, and that Trivy is available (on `PATH` or at `~/.tomofound/tools/trivy`). When all three hold it exits `0` with no network access, no lock and no re-exec.
  - **Locked slow path**: otherwise it builds or updates the venv through `_bootstrap()`, then takes the `~/.tomofound/tools.lock` cross-process lock, re-checks, and installs only what is missing (an up-to-date ATR catalog is not re-downloaded). All output goes to `stderr` so MCP's JSON-RPC `stdout` stays clean.
- Added `_file_lock()`, a cross-process lock (`fcntl.flock` on POSIX; `msvcrt.locking` with an `LK_NBLCK` retry loop and `seek(0)` alignment on Windows). Lock files live in `~/.tomofound/` and are never deleted.
- Packaged tomofound as a Claude Code plugin (while keeping runtime data in `~/.tomofound/`):
  - `.claude-plugin/plugin.json`: plugin manifest (`tomofound`, `version` matching `setup.sh`'s `TOMOFOUND_REF` without the leading `v`, `author`, `MIT` license, `repository`, and `network.hosts` disclosure list, which only declares the outbound hosts and neither allows nor blocks any of them; omits `userConfig` and relies on auto-detection for hooks, MCP servers, and skills).
  - `.claude-plugin/marketplace.json`: single-plugin marketplace (`tomofound`, `owner: {"name": "rotoyang"}`) whose `plugins[0].source` pins `rotoyang/tomofound` on GitHub at the release tag (`ref`) rather than a relative path or `main`.
  - `.mcp.json`: registers the `tomofound` MCP server under `mcpServers` using `python3` and `${CLAUDE_PLUGIN_ROOT}/server/trivy_server.py`.
  - `hooks/hooks.json`: registers an async `SessionStart` hook (`timeout: 600` seconds) executing `python3 "${CLAUDE_PLUGIN_ROOT}/server/trivy_server.py" --ensure-tools`.
- Added `tests/test_plugin_packaging.py`, a static offline test suite verifying three-way version pin consistency (`setup.sh` `TOMOFOUND_REF` == `.claude-plugin/marketplace.json` `ref` == `"v" + .claude-plugin/plugin.json` `version`), marketplace tag pinning (rejecting relative paths, floating branches, and SHAs), `plugin.json` metadata/MIT license/`network.hosts` validity, `.mcp.json` and `hooks/hooks.json` `${CLAUDE_PLUGIN_ROOT}` usage with no hard-coded local paths, and existence of referenced plugin targets.
- Defined `_ATR_LICENSE_SHA256_HINT` in `server/atr_catalog.py` to record the SHA-256 of the last human-reviewed upstream ATR `LICENSE` (`aaf963e77675bc977a3d059b8a2604e7f9fe527b03f005c45df80c1195c92598`, byte-identical at `v3.5.11` and `v4.3.1`). `update_catalog()` keeps the `"MIT License"` text check as a hard gate, records `license_sha256` and `license_changed` in `meta.json` and its return payload, and adds a `license_review` advisory when the hash differs without blocking the update.
- Added support in `server/atr_catalog.py` (`_compile_rule()`, `_condition_is_usable()`, `_parse_rules_dir()`, and `_match_against_catalog()`) for ATR `detection.condition: all` (AND semantics), `status: deprecated` filtering, and per-reason skip counts (`skipped_by_reason` / `rules_skipped_by_reason`):
  - Rules marked `status: deprecated` are skipped at compile time so retired detections do not fire.
  - Rules with `detection.condition: all` require every pattern to match (reporting the finding on the first pattern) and are skipped as a whole if any condition is not evaluable on a static file, avoiding partial-condition false positives; unsupported `detection.condition` expressions are also skipped rather than evaluated as OR. Legacy cached catalogs without a `condition` field continue to default to `any`.
- Added unit tests in `tests/test_atr_catalog.py` covering the `v4.3.1` pin, `detection.condition` (`any`, `all`, unsupported, and legacy catalogs), `status: deprecated` skipping, `skipped_by_reason` reporting, `_ATR_LICENSE_SHA256_HINT` change flagging and non-MIT refusal, `_TARBALL_MAX_BYTES` headroom, and sibling-prefix path traversal rejection.

### Changed
- Renamed `skills/security-scan/security-scan.md` to `skills/security-scan/SKILL.md` (contents unchanged) to follow the Claude Code plugin standard filename.
- Updated `_PROMPT_SOURCE_CANDIDATES` in `server/trivy_server.py` to check `SKILL.md` in the repository and `DATA_ROOT` before falling back to legacy `security-scan.md` paths for backward compatibility with older installations.
- Updated `setup.sh` to fetch `skills/security-scan/SKILL.md` via a temporary file with fallback to `skills/security-scan/security-scan.md` (supporting older pinned refs such as `v0.5.0`), installing `SKILL.md` alongside an identical `security-scan.md` compatibility copy for the `v0.5.0` server.
- Updated skill path references in `README.md` and `CLAUDE.md`, updated existing test paths, and added unit tests in `tests/test_trivy_server.py` covering prompt source candidate ordering and fallback behavior.
- `_bootstrap()` in `server/trivy_server.py` now creates the venv and runs `pip install` under a `~/.tomofound/venv.lock` cross-process lock with a re-check inside the lock (`_venv_ready()`), releases the lock before re-exec, and sends `venv`/`pip` output to `sys.stderr`. This keeps an MCP server start and a background hook from corrupting each other's venv build.
- `_install_tools_cli()` takes a new `skip_current_atr: bool = False` parameter so `--ensure-tools` can skip an already-current ATR catalog, while `--install-tools` keeps its existing always-refetch behaviour.
- Updated `README.md` to split installation instructions between Claude Code (`/plugin marketplace add rotoyang/tomofound`, `/plugin install tomofound@tomofound`, `/tomofound:security-scan`, available from the next release, with migration steps for removing standalone Claude Code MCP registrations) and `setup.sh` (Claude Desktop chat, Codex, and Gemini CLI), and updated the **Supply chain** tables with the new plugin files, `server/atr_catalog.py`, PyPI/plugin network calls, and confirmation that the plugin writes only to `~/.tomofound/`.
- Updated `CLAUDE.md` release instructions so release PRs bump `setup.sh` `TOMOFOUND_REF`, `.claude-plugin/plugin.json` `version`, and `.claude-plugin/marketplace.json` `plugins[0].source.ref` together before merging and tagging, and verify that the published tag contains the plugin files.
- Bumped the pinned Trivy CLI version (`_TRIVY_PIN` in `server/trivy_server.py`) from `0.72.0` to `0.76.2` (2026-11-05 release), updated the matching `README.md` **Supply chain** tables (Runtime dependencies row and outbound download URL), and added `test_readme_supply_chain_tables_match_trivy_pin` in `tests/test_trivy_server.py` to keep `README.md` in sync with `_TRIVY_PIN`. Reviewed `0.73.0`–`0.76.2` changes: picks up `0.76.1`/`0.76.2` security fixes (Go 1.27.3 for `CVE-2026-111943`, `golang.org/x/net` v0.62.0 for `CVE-2026-78661`/`CVE-2026-97045`, `go-jose/v4` v4.1.6 for `GHSA-mgcc-cww5-fp2q`) and `fs` scanner fixes (pnpm workspaces, PEP 621 `pyproject.toml`, `uv` workspace lockfiles, `package-lock.json`, pip extras, `go.sum`, PHP dependencies), with no breaking changes to release asset filenames, `secret` scanning, JSON `SchemaVersion: 2` output, `--db-repository` defaults, or `--version` output format.
- Upgraded the pinned Python `mcp` SDK in `server/trivy_server.py` (`_PIP_DEPS` / `_MCP_PIN`) from `1.28.1` to `1.30.0`, bumped `_DEPS_VERSION` from `"3"` to `"4"` so existing `~/.tomofound/venv` installations automatically reinstall dependencies on next start, updated the `README.md` **Supply chain** table to `1.30.0`, and added unit tests in `tests/test_trivy_server.py` covering the pin, marker mismatch, and MCP tool/prompt listing.
- Upgraded the pinned Agent Threat Rules (ATR) catalog (`server/atr_catalog.py:ATR_PIN`) from `v3.5.11` to `v4.3.1` after verifying the `v4.3.1` tag's MIT `LICENSE` covers the `rules/` data with no additional LICENSE/COPYING files under `rules/`.
- Raised `_TARBALL_MAX_BYTES` in `server/atr_catalog.py` from `60 MiB` to `120 MiB` to leave headroom for the `v4.3.1` source tarball (measured at 59,013,052 bytes vs. 35,116,464 bytes at `v3.5.11`), and updated inline comments with `v4.3.1` measurements (844 rule files) while labeling historical `v3.5.11` numbers.
- Updated ATR version references and tarball size in `README.md` (installation notes, stale-catalog example, Supply chain table, outbound network URLs, and Attribution section) and updated the pinned ATR version from `v3.5.0` to `v4.3.1` in `integrations/codex/skills/security-scan/SKILL.md` and `integrations/gemini/skills/security-scan/SKILL.md`.

### Fixed
